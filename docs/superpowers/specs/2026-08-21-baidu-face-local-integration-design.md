# 智能更衣柜 v13 百度人脸本地联调设计

日期：2026-08-21  
状态：用户已确认，可进入实施计划  
基线：v12（必须完整保留，不覆盖原 APK、构建目录或功能）

## 1. 目标

在现有智能更衣柜 APK 中直接接入百度离线人脸 SDK 8.5，形成以下联调闭环：

1. 用户在首页点击“人脸识别”。
2. 应用才申请并占用终端内置摄像头；首页、手机号、密码等页面不监听人脸。
3. 百度 SDK 在终端本地完成单人脸检测、基础质量判断和最佳帧选择。
4. 应用抓取一张完整画面 JPEG，不裁剪人脸，不写入磁盘。
5. v13 联调版通过可替换的本地模拟校验器自动返回“服务器校验通过”。
6. 校验成功后进入现有选柜页面；此时不自动开柜。
7. 用户选择柜门并确认后，才沿用现有串口链路发送开锁指令。

未来取得正式人脸上传接口后，只替换校验器实现，不重写相机、百度检测、选柜或串口逻辑。

## 2. 本期范围

### 2.1 必须实现

- 直接集成 `FaceSDK_8.5_20241220-release.aar`。
- 仅加载检测、对齐、清晰度、遮挡和最佳帧所需模型。
- 管理员可执行一次性百度在线激活；激活成功后使用应用私有目录中的授权文件进行本地校验。
- 首页“人脸识别”按钮由“设备暂未接入”改为可点击。
- 新增符合现有 1280×800 视觉体系的人脸识别页面、摄像头预览、状态提示和返回入口。
- 完整实现权限、初始化、检测、抓拍、模拟校验、成功进入选柜、失败重试、超时和取消。
- v13 使用真实摄像头和真实百度人脸检测；仅“业务服务器比对结果”是模拟通过。
- v13 是独立的现场联调包，不得作为正式身份认证版本部署；人脸页和由人脸进入的选柜页持续显示“本机联调，未进行身份比对”。
- 保持现有 ID/二维码、手机号、密码、管理员串口和动态选柜功能不变。

### 2.2 明确不做

- 不做本地人脸注册、特征提取、人脸库、1:N 搜索或本地身份比对。
- 不使用 Demo APK 的页面，也不通过 Intent 启动 Demo APK。
- 不做 RGB/NIR/深度活体、属性、口罩、安全帽、注视等能力。
- 不裁剪人脸照片，不保存照片，不显示照片原始数据，不把照片写入日志。
- 不实现甲方服务器、不猜测正式上传接口、不伪造为已经完成服务器联调。
- 不改变柜门协议、串口所有权、柜门检测或开锁确认规则。
- 不在无人点击时常驻打开摄像头。
- 不允许正式构建包含、反射加载或回退到本地自动放行校验器。

## 3. SDK 与设备约束

### 3.1 设备与 ABI

- 目标终端 CPU：RK3288，实际运行架构按 `armeabi-v7a` 处理。
- 百度核心 AAR 的完整人脸运行库仅支持 `armeabi-v7a` 和 `arm64-v8a`。
- v13 人脸版仅打包 `armeabi-v7a`、`arm64-v8a`，不得把缺少 `libbdface_sdk.so` 的 x86/armeabi 声明为可用人脸 ABI。
- 已有百度 Demo 在同一终端成功激活并打开摄像头，证明硬件、Android 版本和 SDK 基本兼容；仍需在更衣柜 APK 中重新验证授权与相机生命周期。
- 百度 Demo 的 `minSdk 21` APK 已能安装在当前终端，证明这台测试机的系统版本不低于 API 21；正式部署前仍必须盘点全部终端的 Android API，低于 21 的设备不能安装 v13 人脸版。

### 3.2 Android 配置

- `minSdk` 从 19 提升到 21，匹配百度 AAR 的最低要求。
- 保持现有 `compileSdk 34`、`targetSdk 30` 和 Java 8。
- 新增 `CAMERA`、`INTERNET` 权限；增加 `ACCESS_NETWORK_STATE`。v13 的百度在线激活本身需要互联网，未来正式图片上传也需要互联网。
- API 23 及以上必须运行时申请相机权限；拒绝后显示明确提示并允许返回。
- 不增加外部存储、电话、系统设置等无关权限。
- Release 继续关闭代码压缩；在百度提供并验证正式 keep 规则前不启用 R8 混淆。

### 3.3 精简模型集合

核心 AAR 固定为 `FaceSDK_8.5_20241220-release.aar`，SHA-256 为 `E77439F9DC4F530FF739F423EC80DA5D0AA1F5F055155FED58CC0BD1B43487E5`。只集成以下六个准确文件：

1. `detect/detect_rgb-customized-pa-192.model.float32-0.0.18.1`
2. `align/align_rgb-customized-pa-fast.model.float32-0.7.5.5`
3. `align/align_rgb-customized-pa-80.model.float32-6.4.14.4`
4. `blur/blur-customized-pa-addcloud_quant_e19.model.float32-3.0.13.3`
5. `occlusion/occlusion-customized-pa-paddle.model.float32-2.0.7.3`
6. `best_image/best_image-mobilenet-pa-dcqe449_live_e51_relu_128.model.float32-1.0.3.1`

不复制 Demo 的完整模型目录。构建时必须校验六个模型均存在，避免缺模型后在真机运行时才失败。

## 4. 授权设计

百度 SDK 的检测能力也受授权控制，不能因为“不做人脸比对”就跳过激活。

### 4.1 激活入口

- 在管理员页面增加“百度人脸 SDK”状态区，显示：未激活、激活中、已激活、授权失效、初始化失败。
- 只有通过现有管理员 PIN 的人员可以进入在线激活和 `LOCAL_DEMO` 启停流程。
- 激活码由管理员现场输入；不得硬编码在源码、资源、APK 或构建脚本中。
- 日志只记录授权阶段和错误码，不记录完整激活码。
- 激活提交后使用 15 秒超时；离开管理员页或应用进入后台时取消本次 UI 等待。失败可由管理员显式重试，不自动循环请求。
- 重复点击激活只保留一个请求；已激活状态下不再显示激活码输入框，除非本地授权校验明确失败。

### 4.2 激活过程

1. 调用百度设备指纹/授权组件取得 SDK 所需设备标识。
2. 使用管理员输入的测试激活码调用百度 SDK 的官方在线激活地址 `https://ai.baidu.com/activation/key/activate`。
3. 成功后由 SDK 将 `license.key`、`license.ini` 保存到本应用私有目录。
4. 后续启动优先执行本地授权校验；已激活时不重复要求输入激活码。
5. 授权无效、过期、包名不符或设备不符时，人脸按钮进入安全失败页，不启动摄像头。
6. 授权有效但模型初始化失败时保留授权文件，允许管理员重新初始化模型，不重复消耗激活码。

Demo APK 的授权文件属于 Demo 包私有数据，不能当作本应用授权文件直接复用。测试激活码能否对 `com.codex.lockertest` 再次激活，以百度激活接口在真机上的实际返回为准。

本应用禁止 Android 备份和调试导出授权文件；授权状态和激活结果写入管理员审计日志，但不记录密钥内容。

## 5. 组件边界

每个组件只承担一个职责，避免把百度 SDK、界面和业务流程堆入 `MainActivity`。

### 5.1 `FaceSdkLicenseManager`

- 提供本地授权状态检查、在线激活和错误映射。
- 不管理相机，不做检测，不持有 Activity。

### 5.2 `FaceSdkRuntime`

- 在授权有效后串行加载 AAR 和六个模型。
- 维护 `UNINITIALIZED / INITIALIZING / READY / FAILED / RELEASED` 状态。
- 百度示例标明识别流程按单线程使用，本组件通过专用单线程执行器串行调用 SDK。

### 5.3 `FaceCameraController`

- 负责打开终端内置前置摄像头、预览、旋转与镜像配置、帧交付和释放。
- 不判断身份，不上传图片。
- 页面返回、Activity `onStop`、超时或成功后立即停止预览并释放相机。
- 为兼容 RK3288 定制系统，首版使用 Android Camera1 API；选择第一个 `CAMERA_FACING_FRONT`，没有前置摄像头时直接失败，不静默切换后置摄像头。
- 分析和抓拍统一使用 640×480 NV21。预览面向用户水平镜像；生成的 JPEG 按 `CameraInfo.orientation` 与屏幕方向旋转为正向，但保持非镜像，JPEG 质量固定 85。
- 打开相机前先枚举前置相机支持的 preview size 和 format；若不同时支持 640×480 与 NV21，则安全失败并记录诊断，不降分辨率、不换格式、不换后置摄像头。
- JPEG 必须能被 Android 解码、包含 SOI/EOI、宽高非零且不超过 1 MiB，才可交给校验器；不写 EXIF 位置信息。

### 5.4 `FaceFrameQualityGate`

- 接收 SDK 的单帧检测结果。
- 要求恰好一张人脸，满足尺寸、位置、姿态、模糊度和遮挡阈值，并在连续 3 个被处理帧均合格后才允许抓拍。
- 多人脸、过远、偏离、模糊或遮挡只更新提示，不触发上传。
- 首版配置固定为百度 8.5 示例值：检测置信度不低于 `0.5`、最小人脸边长 `60 px`、pitch/roll/yaw 绝对值均不超过 `30°`、模糊值不超过 `0.8`、光照分数不低于 `0.8`、眼/鼻/口/面颊/下巴遮挡值不超过 `0.8`、完整度 `1.0`、`FaceInfo.bestImageScore` 大于 `0.5`。
- 每 100 毫秒最多提交一帧给 SDK，最长检测 20 秒。阈值只允许通过一个有版本号的 `FaceQualityConfig` 修改；v13 UI 不提供现场调参入口。

### 5.5 `FaceCaptureSession`

- 管理一次“点击人脸识别”会话和防重复状态。
- 状态：`PREPARING → DETECTING → CAPTURING → VERIFYING → SUCCESS/FAILURE/CANCELLED/TIMEOUT`。
- 每次会话最多存在一张待校验 JPEG 和一个校验请求。
- 所有回调携带会话代次；旧页面、旧相机或旧校验结果不得影响当前页面。

### 5.6 `FaceVerificationClient`

统一接口接收：

- JPEG 字节数组。
- 请求 ID。
- 客户端时间戳。
- 可取消令牌。

统一返回结构 `FaceVerificationResult`：

- `status`：通过、未通过、网络错误、服务器错误、请求取消。
- `source`：`LOCAL_DEMO` 或 `REMOTE_SERVER`。
- `requestId`：必须与请求一致。
- `credential`：通过时必填；正式环境由服务器签发，绑定设备、请求和人脸会话。
- `expiresAt`：凭证失效时间。
- 可选 `userId`、`userToken` 和授权范围；Flow 只保存业务所需的不可变快照，不记录到客户日志。

本期实现 `LocalPassFaceVerificationClient`：

- 接收到通过 SOI/EOI、解码、尺寸和 1 MiB 上限检查且未取消的 JPEG 后，固定延迟 800 毫秒返回通过。
- 不联网、不落盘、不解析身份。
- 管理员运行日志明确记录 `face-verifier=LOCAL_DEMO`，避免误以为已接入正式服务器。
- 日志只记录请求 ID、阶段、耗时和 JPEG 大小，不记录图片内容。
- 返回的 demo credential 只在 v13 demo 构建中有效，来源为 `LOCAL_DEMO`、有效期 60 秒，并绑定本次进程、设备和 requestId。
- v13 人脸页以及由该凭证进入的选柜页持续显示醒目的橙色横幅：`本机联调：未进行身份比对`。
- v13 的本地模拟校验只能由管理员在“人脸 SDK 联调”设置中显式启用；启用动作写审计日志。关闭后人脸校验一律拒绝放行。
- 新安装 v13 或从 v12 升级时 `LOCAL_DEMO` 默认关闭。管理员启用状态保存在应用私有配置中，应用重启和管理员退出不改变它；管理员关闭后立即取消正在校验的 demo 会话并清除其 credential，卸载应用会清除该状态。

未来实现 `HttpFaceVerificationClient` 时保持相同接口，替换依赖注入即可。正式 source set 不编译 `LocalPassFaceVerificationClient`；构建守卫检查 DEX 中不存在 `LOCAL_DEMO` 自动放行实现。

### 5.7 `FaceRecognitionView`

- 延续当前蓝绿科技风格和 1280×800 固定设计基准。
- 显示摄像头预览、检测框、状态文案、返回按钮和超时提示。
- 客户可见文案不展示百度错误码、授权码、设备号、接口地址或图片数据。
- 页面本身不持有业务校验器，所有操作通过监听器交给控制层。
- 联调横幅属于真实 View，不是仅写日志或绘制在不可访问的背景中。

## 6. 页面与业务流程

### 6.1 启动

1. 首页点击“人脸识别”。
2. `KioskFlowModel` 进入新的 `FACE_RECOGNITION` 页面，而不是 `UNAVAILABLE`。
3. 检查授权、模型状态和相机权限。
4. 初始化成功后启动相机并进入检测状态。

### 6.2 抓拍与模拟校验

1. SDK 每帧检测人脸并返回质量信息。
2. 质量门判断稳定合格后锁定一次抓拍。
3. 从完整预览帧生成方向正确、镜像正确的 JPEG；不裁剪。
4. 暂停继续抓拍，状态切换为“正在验证”。
5. 仅当管理员已启用 `LOCAL_DEMO` 时，本地模拟校验器才自动返回通过；未启用时显示联调未开启并留在人脸页。
6. 立即清除 JPEG 字节引用并释放相机。
7. Flow 只接收 `FaceVerificationResult.credential` 并以 `FACE` 进入现有 `LOCKER_SELECTION`；只有 v13 demo client 可以签发 demo credential，客户端不得自行生成正式 credential。
8. 开始现有柜区/柜门加载；进入选柜前串口写入必须为零。进入选柜后只允许现有柜区发现/状态查询帧，客户确认柜门之前严禁任何 `8A` 开锁帧。

### 6.3 选柜和开柜

- 人脸通过后的选柜、翻页、分区、柜门确认和结果提示完全复用现有逻辑。
- `UnlockCredentialAdapter` 只接收“已由 FaceCaptureSession 完成校验”的 FACE 会话凭证。
- Adapter 同时校验凭证来源、设备、requestId 和有效期；正式构建拒绝 `LOCAL_DEMO` 来源。
- 用户在选柜页停留至 credential 过期后点击确认，必须清除选中柜门、区域/页选择和 credential，返回人脸识别页并提示 `验证已过期，请重新识别`；不得延长、刷新或复用旧凭证。
- 失败重试返回人脸识别页并创建新会话，不复用旧 JPEG 或旧校验结果。

### 6.4 返回和生命周期

- 人脸页点击返回或系统 Back：取消校验、停止帧处理、释放相机，回首页。
- `onStop`/`onDestroy`：先使代次失效，再取消校验和释放相机。
- 成功跳转选柜前：先使人脸会话失效并释放资源，再改变页面。
- 回到首页后摄像头必须保持关闭。

## 7. 图片处理与隐私

- 使用完整画面 JPEG，不做人脸裁剪。
- 根据实际摄像头方向修正旋转；前置预览可镜像，但上传 JPEG 的镜像策略固定并记录在配置中。
- `FaceCameraController` 独占可复用 NV21 回调缓冲；处理队列至多保留一帧，不复制和积压旧帧。
- `FaceCaptureSession` 是 JPEG 的唯一所有者，内存中同时最多保留一份标准化 JPEG 和一个正在处理的 NV21 缓冲。
- 校验结束、取消、失败或超时后先取消排队任务，再将 JPEG/临时图像字节覆盖为零并释放引用；如使用 Bitmap，必须在同一终态路径回收并清空引用。
- 不写相册、缓存目录、外部存储、数据库或运行日志。
- 不输出 Base64、像素、特征值或截图到管理员日志。
- v13 的本地模拟校验不得把照片发送到任何地址。
- “完整画面、不裁剪”是甲方当前明确选择，只适用于 v13 不外传联调。正式上传前必须再次确认服务端硬性要求、最大分辨率、用户告知、保留期限和删除机制；未确认时不得启用远程上传。

## 8. 错误处理

### 8.1 客户可见错误

- 未激活/授权无效：`人脸功能尚未就绪，请联系管理员`。
- 相机权限拒绝：`无法使用摄像头，请联系管理员`。
- 相机占用或打开失败：`摄像头启动失败，请重新尝试`。
- 未检测到人脸：持续提示 `请正对摄像头`。
- 多人脸：`请仅保留一人面对摄像头`。
- 人脸过远/偏离/模糊/遮挡：显示对应安全提示。
- 20 秒未取得合格画面：`识别超时，请重新尝试`，提供重试和返回首页。
- 模拟校验取消或异常：`验证失败，请重新尝试`。

相机权限状态细分如下：首次进入才弹系统权限框；普通拒绝后显示“重新授权”按钮；勾选“不再询问”或设备策略禁用时只显示“请在系统设置中允许摄像头”，不反复弹窗；从后台返回时重新读取权限，已撤销则终止旧会话并回到权限提示。

### 8.2 管理员诊断

- 记录 SDK 授权状态、模型加载阶段、相机 ID/方向、检测阶段、质量拒绝类别、会话 ID、模拟校验器类型和耗时。
- 不记录激活码、原始照片、人脸框图像、未来服务器 token 或个人身份信息。

### 8.3 分状态超时

- 本地授权校验与模型初始化：15 秒；超时进入初始化失败，不启动相机。
- 相机打开与首帧：5 秒；超时释放相机并显示启动失败。
- 人脸检测：从预览首帧起 20 秒；超时停止会话并提供重试。
- JPEG 标准化：3 秒；超时丢弃所有图像缓冲。
- v13 本地模拟校验：3 秒上限，正常固定在 800 毫秒完成。
- 未来正式 HTTP 校验：默认 10 秒，最终以服务端协议为准。
- 终态采用“先到达者生效”：取消、超时、成功、失败只有第一个能完成会话；后到回调全部丢弃，且必须取消对应定时任务。

## 9. 并发与稳定性规则

- 百度 SDK 调用固定在单线程执行器中，禁止多帧并行推理。
- 相机帧使用有界的“只保留最新帧”策略；处理不过来时丢弃旧帧，不积压 Bitmap/YUV。
- 抓拍和校验期间不再接受第二次抓拍。
- UI 回调统一先投递主线程，再校验 Activity 状态、UI 代次和 FaceCaptureSession ID。
- 取消操作幂等；相机、执行器任务和 JPEG 资源只能释放一次。
- 人脸模块不得关闭或重建进程级串口 Gateway。
- 从点击人脸到进入选柜，客户侧串口发送边界对每次 write 记录来源与帧类型；断言写入数为 0。进入选柜到确认柜门期间只允许拓扑/状态查询白名单，`8A` 帧计数必须为 0；唯一开锁入口仍是确认后的 `UnlockCredentialAdapter → UnlockCoordinator`。底层冻结的 `SerialGateway` 不需要为此改动。
- 当前选柜白名单只包含 `BoardStatusProtocol.query(1..3)` 各至多一次：`80 01 01 33 B3`、`80 02 01 33 B0`、`80 03 01 33 B1`。其他串口写入均拒绝；未来如需新增查询帧，必须先扩展枚举与回归测试，不能使用“任意非 8A”通配规则。

## 10. 测试策略

### 10.1 纯 JVM 测试

## 11. 未来服务器替换边界

正式接口文档到达后新增 `HttpFaceVerificationClient`，不得修改百度检测、摄像头或选柜模块。服务器结果直接构造同一 `FaceVerificationResult`，其中服务器 credential/token、有效期和权限声明完整传递给 Flow；客户端不得自行生成正式 credential。

正式 credential 采用服务端返回的 opaque token。客户端不解释或自行伪造其业务内容，只在后续受 TLS 保护的领柜/开柜请求中原样提交，由服务端验证设备、用户、requestId、权限和有效期。`REMOTE_SERVER` 结果只能由包内受限的 `HttpFaceVerificationClient` 工厂创建，UI、Flow 和 JSON 字段不能直接指定 source。若服务端最终采用签名 token，则接口文档还必须提供签名算法、密钥轮换和客户端验签要求；在任一可信方案未明确前，正式人脸功能保持关闭。

客户端至少需要明确：

- HTTPS 路径和请求方法。
- `multipart/form-data` 或二进制上传格式。
- 图片字段名、最大字节数、JPEG 质量限制。
- 设备标识、请求 ID、时间戳和鉴权/签名规则。
- 成功、未登记、网络错误、服务器错误和重复请求的返回结构。
- 服务器通过后返回的会话 token 或一次性授权凭证。
- 超时、重试和幂等要求。

正式版规则：断网、接口缺失或服务器未通过均禁止进入选柜；不得回退到本地模拟通过。现有 `checkDevice` 接口只用于设备备案，不能替代人脸图片上传/比对接口。

## 13. 验收结论定义

v13 只有同时满足以下条件才可称为“本地人脸联调完成”：

- 本更衣柜 APK 自己完成百度授权、本地模型初始化、相机预览、人脸检测和真实抓拍。
- 抓拍图片不落盘、不外传。
- 本地模拟校验通过后稳定进入现有选柜页。
- 联调横幅全程可见，正式构建无法包含或接受本地模拟凭证。
- 未选择并确认柜门前不发送开锁命令。
- 退出/后台/超时没有相机泄漏或旧回调跳页。
- v12 交付件及原有所有识别、选柜、串口功能保持不变。

这不代表服务器人脸比对已经完成；正式服务器联调必须在取得明确上传接口后另行验收。
