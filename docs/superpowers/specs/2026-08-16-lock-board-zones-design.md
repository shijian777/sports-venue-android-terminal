# 锁控板回包修复与 A/B/C 分区设计

## 已确认范围

- 修复 02–12 柜实体开门后被误判为通信超时的问题。
- 保持厂家给定的板 01、锁 01–12 开锁指令逐字节不变。
- 支持三块 12 路锁控板：拨码地址 01、02、03 固定映射为顾客端 A、B、C 区。
- 顾客端只显示 `A区/B区/C区` 与 `A1…A12/B1…B12/C1…C12`；不显示板地址、HEX、串口或校验信息。
- 串口保持现有进程级长连接；检测与开锁不并发，一次只允许一个待响应命令。
- UI 只以 1280×800 为本轮设计和验收目标。
- 终端服务器备案只提供方案，本轮不实现网络、权限、接口或备案页面。
- 管理员串口调试助手的四个可见构建方法保持逐体一致。

## 厂家协议依据

所有校验字节均为前序字节的 BCC/XOR。开锁发送帧为：

```text
8A <板地址> <锁地址> 11 <XOR>
```

被动反馈帧为：

```text
8A <板地址> <锁地址> <00或11> <XOR>
```

当前设备按“上锁短路型”处理：`00` 为开锁成功，`11` 为开锁失败。保留显式反馈极性类型，以便未来兼容“开锁短路型”。发送开锁命令期间，`82` 开头的主动反馈只进入管理员原始日志，不作为本次开锁结果。

板 01 的 12 个成功帧必须是：

```text
8A0101008A  8A01020089  8A01030088  8A0104008F
8A0105008E  8A0106008D  8A0107008C  8A01080083
8A01090082  8A010A0081  8A010B0080  8A010C0087
```

## 板卡检测

不使用开锁命令探测。进入选柜流程前，在现有串口连接上依次发送厂家“查询单锁状态”命令，固定查询每块板的锁 01：

```text
80 <板地址> 01 33 <XOR>
```

本版本只检测地址 01、02、03：

```text
地址01：80 01 01 33 B3 → A区
地址02：80 02 01 33 B0 → B区
地址03：80 03 01 33 B1 → C区
```

合法回包为 `80 <同一板地址> 01 <00或11> <正确XOR>`。`00` 和 `11` 都只表示“板卡有响应”；查询回显、错误校验、错误地址、`82` 主动反馈、`8A` 开锁反馈和晚到的旧回包均忽略。

- 严格顺序检测 A→B→C，一次只有一个查询在途。
- 连接复用前必须逐字段确认当前串口仍是 `/dev/ttyS0`、9600/8N1、flags 0；若管理员留下其他配置，顾客流程先安全关闭，再按默认配置打开，默认配置确认前发送 0 条检测/开锁帧。
- 每次扫描开始先保持至少 300 ms 接收静默期；静默期收到任何旧字节就重新计时，用于排除上一次操作的晚到回包。
- `SerialGateway.send()` 只代表入队；响应计时从对应 `onSent` 到达后开始。若合法响应在线程调度上早于 `onSent` 到达，暂存该帧并在匹配的 `onSent` 到达后完成，不能丢弃。
- 发送入队后 1 秒仍没有 `onSent` 或带负载关联的发送失败事件，扫描安全失败，不能永久等待。
- 每个地址响应窗口 300 ms；成功或超时后保留 20 ms 总线静默间隔。
- 每个地址只查一次，不自动重试，不发布中途结果。
- 三个地址全部完成后一次性发布在线分区快照。
- 系统 Back、进入管理员、Activity 停止、串口故障或新一代扫描会取消旧计时器并使旧回包失效。所有串口监听回调都必须无条件 `Handler.post` 后再检查页面代次和进程串口租约，禁止用可能在主线程内联执行的 `runOnUiThread` 进入 owner 操作。
- 若没有板响应，禁止选择和开锁，显示“暂无可用柜区，请联系管理员”。

固定地址映射避免危险的自动重命名：即使 A 区板离线，地址 02 仍然是 B 区，绝不补位成 A 区。安装时必须把三块板的拨码分别设为 01、02、03；重复地址无法由软件可靠区分，必须现场排除。

## 顾客端模型与交互

新增不可变目标：

```java
LockerTarget(
    LockerZone zone,       // A/B/C
    int boardAddress,      // 1/2/3，仅协议和管理员日志使用
    int lockAddress,       // 1..12
    FeedbackPolarity polarity
)
```

- 协议、检测器和协调器使用 `boardAddress + lockAddress`。
- 顾客文案只使用 `target.customerLabel()`，返回 `A1…C12`。
- 选柜页顶部显示 A区/B区/C区切换；在线分区为绿色可点，离线分区为灰色不可点。
- 下方始终只有一套 3×4 网格；切换分区时按钮文字随之变为 A1…A12 等。
- 切换分区清除旧选择，防止不可见柜门继续可确认。
- 开锁失败/超时后“再次尝试”恢复原分区与原柜号，但必须再次点击确认才发送。
- 确认后捕获不可变 `LockerTarget`，后续扫描结果变化不能改写本次物理目标。
- 每次开锁发送前同样等待至少 300 ms 接收静默期；静默期旧帧只记管理员日志并重新计时，不能结束新请求。协议没有请求序号，超过厂家最大反馈延迟仍到达的同板同锁旧帧在字节层无法区分，因此真机验收必须验证反馈延迟不超过此保护窗口。

## 1280×800 UI

- 保留现有科技背景、标题、页脚、三列首页、选柜网格和提示弹层。
- 首页三列由 31/37/32 调整为 28/44/28，中间输入、键盘和确认区获得更多空间。
- 选柜页使用 ZIP 设计单位而不是密度相关的固定 dp；只验收 1280×800。
- 分区切换行占用选柜说明与网格之间的固定区域，不缩小 3×4 按钮触控面积。
- 顾客可见及无障碍文案禁止出现 `board`、`板01`、`tty`、`/dev/`、`HEX`、物理地址和校验字节。

## 终端备案解决方法（本轮搁置）

这份锁控板协议没有读取终端唯一序列号的命令，因此备案身份不能从锁控板推断。后续采用可替换的 `TerminalIdentityProvider`：

1. 首选终端厂家提供的出厂固化 SN 接口、系统属性或预装服务。
2. 若厂家不提供，使用 `ANDROID_ID` 作为“安装备案号”，并接受恢复出厂或换签名后重新备案。
3. 首次备案时由 Android Keystore 生成密钥对，将公钥与 SN/安装号绑定；APK 不内置长期公共密钥。
4. 启动后通过 HTTPS 查询 `REGISTERED / UNREGISTERED / SUSPENDED / REVOKED`。
5. 已备案才进入现有首页；未备案显示用户给出的异常提醒、序列号和刷新按钮；网络异常必须单独显示，不能冒充未备案。
6. 首次无网默认拒绝进入；已备案设备可使用服务端签名、短期有效的离线授权。

实施前必须向终端厂家确认：是否存在每台唯一、出厂固化且普通/预装 APK 可可靠读取的终端 SN。

## 验收

- 板 01 的 12 条发送帧与用户提供表完全一致。
- 板 01 锁 02 收到 `8A01020089`、锁 12 收到 `8A010C0087` 均判成功，不再超时。
- A/B/C 任一目标只接受同板同锁且 XOR 正确的被动反馈。
- `82` 主动反馈、错误板、错误锁、错误校验、旧尝试均不能结束开锁请求。
- 检测只发送三条 `80` 查询，不发送任何 `8A` 开锁命令。
- A1、B1、C1 分别生成板地址 01、02、03 的正确开锁帧。
- 单板、双板、三板及无板四种真机状态均有明确 UI；离线分区不可确认。
- 管理员串口调试助手可见布局保持基线一致，原始 Send/Read 日志完整保留。
- 1280×800 无重叠、裁切或触控拥挤。
